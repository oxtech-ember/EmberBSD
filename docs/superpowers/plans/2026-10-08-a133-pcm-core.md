# A133 PCM Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Supply silent, tested format and buffer primitives for the A133 audio driver.

**Architecture:** Keep the portable A133 core separate from the legacy sunxi codec driver. Production source and host/native contracts share exactly the same implementation; hardware integration follows separately.

**Tech Stack:** NetBSD KNF C99, shell, macOS Clang and native NetBSD/aarch64 GCC.

**Spec:** ../specs/2026-10-08-a133-pcm-core-design.md

## Global Constraints

- No MMIO, playback, recording, GPIO or supply changes.
- Signed little-endian 16-bit PCM at 16000 or 48000 Hz: mono playback/capture and stereo playback.
- Mode is exactly PLAY or RECORD, not a bitset.
- Invalid input leaves caller-owned results unchanged.
- No heap allocation or callback occurs in the core.
- Do not enable this core in the kernel configuration or replace a working kernel.

## Review Focus

- Invalid combined directions must not silently select playback.
- Unsupported formats must not enable hardware or partially update configuration.
- Overflow in buffer geometry must not admit less than two blocks.
- Odd FIFO byte budgets must not split a stereo frame or cross a block.
- Buffer wrap must preserve sample order and report each block exactly once.
