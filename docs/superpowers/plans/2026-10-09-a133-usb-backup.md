# A133 USB backup acquisition implementation plan

> **For agentic workers:** Use superpowers:executing-plans inline task-by-task.

**Goal:** acquire a private per-device USB backup including hardware boot areas.
**Architecture:** extend capture schema2, then use the bounded ADB channel for read-only acquisition.
**Tech Stack:** Ruby standard library; existing GPT/capture/channel tools.
**Spec:** [USB backup design](../specs/2026-10-09-a133-usb-backup-design.md).

## Global Constraints

- Fixed production eMMC31037849600/17-partition inventory; no production test mode.
- Directory/parent0700, input/output files0600, same UID; no existing destination adoption.
- Schema1 compatibility; schema2 includes state/root method and boot0/boot1 hashes/bytes.
- Retain/check all inputs, reject inode aliases, normalized errors have no private cause.
- Read-only USB commands; no device writes, reboot, unlock, audio/camera or ready=true.
- Raw output, complete stream length/hash, fresh host verification before final manifest.
- Live Android consistency stays unestablished; no physical acquisition acceptance.

## Review Focus

- A live snapshot or schema1 record must not imply quiescent/hardware/full installer readiness.
- Root wrapper, identity pinning and stream bounds must prevent wrong-source or truncated success.
- Publication must never replace existing outputs; failure preserves partial evidence.
- Boot-area aliases/mutation and local filesystem faults must refuse a successful receipt.
- Deadline/remote errors and full exception logging must remain bounded and private.

## Evidence and decisions

Initial implementation: `54bc6368c35d`, `037b53c84f17`. Hardware18, acquisition26,
late-lifetime5, capture37, capture-review-regression6, library14 and backup29
passed on Ruby4.0.5/system2.6.10. Channel13/transfer43/session25/environment
passed on Ruby4 after the fixes. Host CLI with no Android ADB refused before
creating a capture directory. No physical backup/image reread/audio/camera,
kernel/userland change or native OS rebuild was performed.

Independent GPT-6 Astra review found one Important lifetime/publication gap,
no Critical/Minor. It reran acquisition26/hardware18/capture-regression6 and
reproduced late boot mutation. Five valid mutations failed against the pre-fix
collector on both Rubies, then passed after the implementer's fix. A test-only
Mac /var versus /private/var string comparison initially failed to inject two
postpublication faults; File.identical? plus explicit fault-execution assertions
corrected the fixture, and both valid RED runs used isolated git-show code.
The reviewer examined the pre-fix range, not the fix pass.

Decisions and costs:

- Continue inline in the existing worktree under autonomous authorization;
  scope is reviewed through these saved artifacts and final independent review.
- Raw storage avoids a compressor pipeline; cost is about31GB plus copies and
  outstanding physical/full-size acquisition acceptance.
- Physical vendor su/ADB/eMMC compatibility remains unaccepted; the fixture
  validates command/stream policy without establishing hardware support.
- Root/recovery/quiescent/restore/firstboot remain pipeline obligations; no
  implicit root restart or release. Cost: a backup cannot mark installation ready.
- Live consistency and power loss remain unestablished; cost: separate quiescent
  copies, restoration and cold cycles are still necessary.
- Source/metadata are trusted, not cryptographically attested; cost: callers
  must establish physical trust and fresh guards before device writes.
- Wiki acceptance is checked/published separately by the implementer;
  code review alone does not confirm external documentation.

Keep the draft PR/worktree; no main merge or permanent boot/device write.
