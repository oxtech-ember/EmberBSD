# RTL8821CE PCIe driver

## Status and limits

The driver attaches PCI device `10ec:c821`, reads its EFUSE identity, and
starts the chip using the separately distributed rtw88 firmware. Hardware
validation on an amd64 device included individual successful sessions with
scanning, WPA2-PSK/CCMP association, DHCP, IPv4 connectivity and HTTPS over
2.4 GHz, 20 MHz legacy 802.11g, without observed DMA, RX, or TX errors.
Starting or restarting the interface often leaves it unable to receive frames
(RX=0); reliable station support has not yet been accepted. Page 0 and page 1 PHY status is bounded and converted from vendor power to a
relative 0–100 signal index; one hardware page 0 sample was verified. This is
not a calibrated RF measurement. 5 GHz, HT, Bluetooth coexistence and power
management have not been accepted.

The current chip implementation advertises 2.4 GHz, 20 MHz, and one spatial
stream. Its PHY and Wi-Fi-only antenna configuration admit RFE profiles 0, 2,
4, and 6; other profiles are refused. These are implementation limits, not a
claim about all hardware capabilities.
A legacy basic-rate probe request may transmit before IQK after a beacon has
authorized the existing passive-channel probe path. This does not establish
reliable RX or calibrated RF operation.

## EFUSE and firmware contracts

The EFUSE layout and chip profile derive from FreeBSD rtw88 at commit
[`a143197801c680b958ab662c88cf086668a1958b`](https://github.com/freebsd/freebsd-src/commit/a143197801c680b958ab662c88cf086668a1958b):
[`rtw8821c.c`](https://github.com/freebsd/freebsd-src/blob/a143197801c680b958ab662c88cf086668a1958b/sys/contrib/dev/rtw88/rtw8821c.c),
[`rtw8821c.h`](https://github.com/freebsd/freebsd-src/blob/a143197801c680b958ab662c88cf086668a1958b/sys/contrib/dev/rtw88/rtw8821c.h), and
[`rtw8821ce.c`](https://github.com/freebsd/freebsd-src/blob/a143197801c680b958ab662c88cf086668a1958b/sys/contrib/dev/rtw88/rtw8821ce.c).
The donor offers GPL-2.0 or BSD-3-Clause; this adaptation is available under
BSD-3-Clause. The common bounded record expander is `rtw88_efuse.h`.

The PCI MAC is at logical offset `0xd0`; the 512-byte physical map has
96 protected bytes and expands to a 512-byte logical map. The decoder accepts
nonempty physical prefixes up to 512 bytes and never interprets the protected
last 96 bytes as records. Truncated records, logical overflow, and invalid
station addresses leave output unchanged. The identity check recognizes PCI
`10ec:c821` and rejects test silicon; it makes no claim about individual cuts
or RFE configurations. Calibration data is raw and does not define regulatory
or transmit-power policy.

The firmware profile describes `rtw88/rtw8821c_fw.bin` from linux-firmware
commit `0a62bdcabeae4666e87f3fba3b7fe116d7414034`, SHA-256
`2ef409bc418549fcf294061dd0cae1fc22fd9da79b60524950b25de18732f3f0`;
its separate license is `LICENCE.rtlwifi_firmware.txt` in linux-firmware.
The 139472-byte image has signature 0x8821 and DMEM/IMEM/EMEM sections of
31976/63240/44168 bytes. A profile validates structure, not authenticity.

Run `ember/tools/rtw8821c-efuse-contract.sh` and
`ember/tools/rtw8821c-fw-contract.sh` through the SDK native-check interface
as described in [`ember/tools/native-net80211-checks.md`](../../../ember/tools/native-net80211-checks.md).
These source-level contracts perform no hardware access and do not by themselves
establish firmware execution, RF operation, or device support.

## Packet descriptors

The packet codec follows the same pinned donor's
[tx.c](https://github.com/freebsd/freebsd-src/blob/a143197801c680b958ab662c88cf086668a1958b/sys/contrib/dev/rtw88/tx.c),
[tx.h](https://github.com/freebsd/freebsd-src/blob/a143197801c680b958ab662c88cf086668a1958b/sys/contrib/dev/rtw88/tx.h),
[rx.c](https://github.com/freebsd/freebsd-src/blob/a143197801c680b958ab662c88cf086668a1958b/sys/contrib/dev/rtw88/rx.c), and
[rx.h](https://github.com/freebsd/freebsd-src/blob/a143197801c680b958ab662c88cf086668a1958b/sys/contrib/dev/rtw88/rx.h).
The fixed TX packet descriptor is 48 bytes, and the donor checksum helper XORs
the first 32 bytes as little-endian halfwords. The donor PCI fill path does
not establish that hardware requires this checksum. Nonzero DATA_SC is refused
until supported by evidence for this selected donor; this is not a claim that
the hardware lacks the field. RX validates the 24-byte header and complete
driver-info, shift and packet bounds before publishing output.

Run `ember/tools/rtw8821c-packet-contract.sh` through the SDK native-check
interface described in [native checks](../../../ember/tools/native-net80211-checks.md).
Set `RTW8821C_PACKET_ANALYZE=1` through the SDK-selected env role with Clang and
cppcheck roles for its explicit analyzer mode. The fixture checks source-level
encoding and bounds only; it does not establish PCI, RF or device operation.
