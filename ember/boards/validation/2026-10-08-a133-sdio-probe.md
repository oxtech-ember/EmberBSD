# A133 opt-in SDIO discovery on one YS-M33 sample

Validation date: 2026-10-08. This is native SDIO host/card discovery from RAM,
not a working WLAN driver or a deployed kernel update.

## Implementation and checks

The early A133 FDT adapter translates the inspected vendor MMC1 only with
the zero-length root `ember,ys-m33-sdio-probe` opt-in. It uses the native
A100 MMC driver, PG0..PG5/mmc1, bus/module clocks 67/63, reset 16, SPI40
level-high and a 25 MHz ceiling. It retains four-bit, non-removable operation.

Guards check complete compatibility strings, the exact register resources,
identity address mapping, legacy pin group, R_PIO/GIC bindings and phandle
resolution. Alternate IRQ, card-detect/write-protect GPIO and power-sequence
properties reject translation. PIO `vcc-pg-supply` also rejects translation:
the pinctrl driver could otherwise enable a regulator. MMC supply references,
UHS requests and sleep pinctrl are removed from the probe host. Provider
nodes and unrelated consumers remain intact. The final enabled compatibility
and status are published only after resource updates succeed.

An ownership marker permits idempotent revalidation. Missing/malformed opt-in
or altered owned resources disables the host and withdraws its marker.
An unrelated canonical host without the marker is not disabled.

- The new production-source contract failed before implementation, then passed.
- Independent read-only source review found five important guard defects:
  PG regulator enable, alternate IRQ, address translation, provider identity
  and malformed string lists. Twelve separately run negative variants
  reproduced the unsafe host marker before the fixes. Expanded contracts
  reject these cases, including stale owned-host cases.
- All nine A133/Goodix/audio/SDIO production-source contracts passed on macOS
  and native NetBSD 11/aarch64. The SDIO contract also passed macOS ASan/UBSan.
- A fresh native GCC 12.5 build compiled the full `EMBER64_A133_AUDIO` kernel
  in a separate exported source directory. The final source pin is
  `43c39c0f3ecd69c0f352133d35da917da9a98432`; its updated adapter was rebuilt
  and relinked using NetBSD 11's matching `dbsym` tool.
- The saved full vendor FDT also passed the production guard in a host harness.
  This is a description check, separate from physical discovery below.

## RAM artifact and physical result

The ARM64 Image is 16,989,924 bytes. The private Android v2 container is
17,002,496 bytes, with an empty ramdisk and the preceding container's
8,351-byte DTB payload. That payload's original provenance is not established;
vendor U-Boot supplies the inspected full board tree at boot. Header, payload,
addresses, alignment and the 32 MiB limit were verified. Container SHA-256:
`5b3d17c5c46d6aaf73f0e084bf29d5aa40a13fd85a31e57e5d869cc61b030f83`.

After a software reboot the UART relay intercepted vendor U-Boot. Only the
volatile root opt-in and USB device-mode setting were added; no environment
save or firmware replacement was performed. USB downloaded the container
to `0x41000000`; it was copied to `0x45000000` before `bootm`. Vendor CRC32
matched `5a934050`. MCU keepalive was serviced during the loader interval.

Physical kernel `EMBER64_A133_AUDIO #1` identified:

```text
sunximmc1: interrupting on GIC irq 72
sdmmc1: 4-bit width, 25.000 MHz
(manufacturer 0x24c, product 0xd723, standard function interface code 0x7)
    at sdmmc1 function 1 not configured
```

The original eMMC host/root, Ethernet/SSH, MCU keepalive, Xorg and awesomeWM
remained active. X reported 1280x800 and registered the touch input device;
operator touch interaction was not requested. Read-only audio control
reported both routes disabled and playback/capture open, active and sample
counts zero. Inspected PMIC registers matched their pre-probe values. No
physical playback or microphone recording occurred. An unprivileged native
C TLS request through the existing external transport returned HTTP 200,
with peer/hostname verification and no authorization header.

The diagnostic did not write eMMC. A subsequent ordinary software reboot,
without UART interception, restored the installed audio kernel `#0`.
Xorg/awesomeWM, Ethernet and MCU keepalive restarted; audio remained off.
The complete 32 MiB boot wedge SHA-256 before and after the probe matched:
`cb2ce60aceaa4ef31d76ee4a25eafa9653357509bb9de55a8b6630a5d2a95b72`.

## Remaining boundary

Function 1 has no attached native network driver. SDIO register/data transport,
radio firmware, WPA association, throughput and reconnect remain unverified.
No network credentials belong in this source tree. Discovery after a warm
reboot does not establish cold power sequencing, SDIO IRQ traffic or sustained
stability. Existing PMIC interrupt/frequency-control warnings and the missing
physical keyboard remain outside this probe; no general stability claim is made.
