# YS-M33 RTL8723DS function enable and restoration

Validation date: 2026-10-08. A RAM-only NetBSD kernel enabled SDIO function 1,
observed IORx ready, repeated SYS_CFG1 and restored IOEx on the physical sample.
This does not initialize the MAC/radio or supply a wireless network interface.

## Implementation and checks

Hardware source pin: `716a317a1a99782b6a6365e7326558dae737f454`.
`EMBER64_A133_SDIO` requires the existing board/card/host guards and a third
zero-length root property, `ember,ys-m33-rtl8723ds-function-probe`.
Default and read-only boots do not enable the function.

The lifecycle uses CMD52 on function-zero IOEx/IORx only. It rejects
already-enabled function ownership, preserves the original IOEx byte, checks
host/R5 errors and verifies write readback. Ready polling allows at most 100
ten-millisecond waits. A failed write retains rollback state because a lost
response does not establish that the card ignored the write. Restore mismatch
is an error and can be retried. The native command adapter rejects RAW,
other functions, other addresses and reserved bits on permitted writes.
No PMIC, MAC, firmware, block-size, interrupt or CMD53 writes are introduced.

The production contract first failed with the lifecycle absent, then passed.
It covers success, preservation of other function bits, prior ownership,
early host failures, ambiguous writes, R5 flags, finite ready timeout,
restore mismatch/retry and write guards. All eleven related
FDT/pin/touch/audio/SDIO/read/function contracts passed in NetBSD 11/aarch64.
The function contract passed macOS ASan/UBSan. Native compilation caught
missing `libfdt.h` and `sys/proc.h` declarations; the corrected pinned source
compiled and linked with GCC 12.5.

## RAM boot

ARM64 Image: 16,991,844 bytes, SHA-256
`e782a9bbace9f26f4fd86f1f67671ad1bb3913ddf37f0bf1a8fe41441b0b1412`.
Android v2 container: 17,004,544 bytes, SHA-256
`c98420e2bd154511efcd1c0949788d73d040b900a9f88400ec193ea261c8bb21`.
The container retained the previous empty ramdisk and 8,351-byte DTB payload;
vendor U-Boot supplied its full board FDT. The payload's original provenance
remains unestablished.

Only volatile loader FDT properties were changed. A local Ruby/libusb
diagnostic downloaded the hash-checked container through USB to `0x41000000`.
UART copied it to `0x45000000` before boot. No environment was saved.

The final lifecycle line requires enabled SYS_CFG1 to agree with the preceding
disabled read. An ordinary reboot returned to installed `EMBER64_A133_AUDIO #5`.
Ethernet/SSH and application services restarted. The complete 32 MiB boot
wedge SHA-256 before, during and after the RAM test was
`a3a5dbc0aee395f2638a33632e7f4f190293080937a69072af3652ca1cf5491a`.
No diagnostic kernel was installed on eMMC.

Chip power sequencing, powered CMD53/block transfers, firmware loading,
SDIO interrupts and net80211 integration are still required. Association,
DHCP, WPA2 traffic, reconnect and cold radio startup were not tested.
