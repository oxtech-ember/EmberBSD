# A133 RTL8723DS read-only transport on one YS-M33 sample

Validation date: 2026-10-08. Native CMD52 register reads succeeded on the
physical tablet from a RAM kernel. This is a diagnostic transport milestone;
it does not supply a WLAN interface or establish radio initialization,
firmware loading, WPA association or reconnect.

## Sources and guarded implementation

The clean source pin is `7e988a6164d810ebe2dc162ea2e9015a673d10d5`.
The separate `EMBER64_A133_SDIO` configuration includes the preceding audio
configuration and a synchronous, one-shot `rtl8723dsprobe` attachment.
Matching requires the actual sunximmc MMC1 FDT parent, a pure I/O card,
common function-0 CIS `024c:d723`, function 1/interface 7, the translated
host marker, and both zero-length root properties:

```text
ember,ys-m33-sdio-probe
ember,ys-m33-rtl8723ds-read-probe
```

Absent, malformed or foreign matches issue no new commands. The read helper
validates local/MAC address domains, encodes CMD52 without write/RAW bits,
reports host and R5 errors, and publishes a four-byte result only after all
bytes succeed. The probe stops on the first failure. It does not enable a
function, change block size, issue CMD53, write chip/CCCR/PMIC registers,
install interrupts, load firmware or create an ifnet. Existing SDIO core
discovery operations remain outside this diagnostic's read-only scope.

Protocol constants and MAC-off byte-access behavior were checked against
Linux v6.12, commit `adc218676eef25575469234709c2d87185ca223a`:
[rtw88 SDIO implementation](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/drivers/net/wireless/realtek/rtw88/sdio.c),
[address definitions](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/drivers/net/wireless/realtek/rtw88/sdio.h),
[chip register definitions](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/drivers/net/wireless/realtek/rtw88/reg.h)
and [RTL8723DS device identity](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/drivers/net/wireless/realtek/rtw88/rtw8723ds.c).
The helper retains upstream authorship and the BSD-3-Clause option of
rtw88's dual license. The native attachment is EmberBSD BSD-2-Clause code.

## Tests and native build

- The new production-source read contract first failed with the helper absent,
  then passed. It covers domain edges, byte order, every partial-read failure,
  R5/host errors, unchanged output on failure, and FDT/card/parent guards.
- All ten A133/Goodix/audio/SDIO/read contracts passed on macOS and native
  NetBSD 11/aarch64. The new contract also passed macOS ASan/UBSan.
- Native GCC 12.5 compiled and linked `EMBER64_A133_SDIO`. The compiler caught
  an incorrect CCCR macro name, corrected in the source commit before export.
- One independent source/lifecycle review found no Critical/Important issue.
  Exact failed byte argument/raw R5 logging remains a deferred minor; current
  failure reporting includes the stage and errno. Native build and physical
  behavior were verified separately by the executor.
- The first RAM kernel booted but did not attach: NetBSD prints the common
  CIS while attachment arguments contain optional per-function IDs. A
  regression executes the actual native match body with absent per-function
  MANFID, first failing and then passing after matching the validated common
  CIS. The rebuilt kernel's live log below confirms this distinction.

## RAM artifact and physical evidence

The final ARM64 Image is 16,991,204 bytes, SHA-256
`31c13823b7c2ef73705fc43e484028c4291f41df1348f964fffdb0b5d4c626d0`.
The private Android v2 container is 17,004,544 bytes, SHA-256
`9c5080b4d54279ebcca97d3a97a9c87bfd2a2f0af3e45acac22dae8c81746cca`.
Header, payloads, load addresses, page alignment and the 32 MiB limit passed
checks. It retained an empty ramdisk and the preceding 8,351-byte DTB payload;
that payload's original provenance is not established. Vendor U-Boot supplies
the inspected full board FDT at boot.

UART intercepted a software reboot. Only volatile FDT opt-ins and USB
device-mode selection were set; no saved environment or firmware replacement.
USB downloaded RAM at `0x41000000`, then the container was copied to
`0x45000000` before boot. Loader CRC32 matched `e2c5ddc0`. MCU keepalive was
serviced during this interval. The physical RAM kernel logged:

```text
NetBSD 11.0 (EMBER64_A133_SDIO) #1: Thu Oct 8 06:40:57 UTC 2026
sdmmc1: 4-bit width, 25.000 MHz
rtl8723dsprobe0 at sdmmc1 function 1: RTL8723DS read-only diagnostic (no network interface)
rtl8723dsprobe0: CIS card=024c:d723 function=0000:0000
rtl8723dsprobe0: CCCR enable=00 ready=00 (unchanged)
rtl8723dsprobe0: SYS_CFG1=00413131 SYS_CFG2=0000000f HSUS=03
rtl8723dsprobe0: CMD52 reads completed; radio not initialized
```

The final line requires repeated SYS_CFG1 to equal the first value. Registers
were read with the function disabled; their values alone do not establish
powered radio, chip revision interpretation, firmware readiness or packet I/O.
Ethernet/SSH, MCU keepalive, Xorg and awesomeWM remained active; X reported
1280x800. Both audio routes remained disabled and playback/capture open,
active and sample counts were zero. No sound or microphone test occurred.

An ordinary reboot without interception restored the installed
`EMBER64_A133_AUDIO #0`. Graphical services, Ethernet and MCU keepalive
restarted with audio off. The full 32 MiB eMMC boot wedge retained SHA-256
`cb2ce60aceaa4ef31d76ee4a25eafa9653357509bb9de55a8b6630a5d2a95b72`.
No diagnostic image was written to eMMC.
