# YS-M33 / Allwinner A133

[Board catalog](README.md) · [Build instructions](../../README.ember.md#building)

Experimental support for one desktop tablet sample with 1 GiB RAM, 32 GB
eMMC and a portrait framebuffer mounted as a landscape screen. The tested
path retains vendor boot0, BL31, OP-TEE, U-Boot and display initialization.
It does not replace the device's secure boot chain or provide a universal
installer. Board revision and exact panel assembly revision are not recorded.

A separate [U-Boot v2026.10 RAM probe](validation/2026-10-08-a133-uboot-ram.md)
reached an interactive second-stage prompt and handed the installed kernel
through to its FFS root. A prearmed 16-second watchdog restored ordinary
EmberBSD without boot/environment writes. It is not installed in eMMC;
sustained operation and direct USB recovery through it remain unverified.

## Capabilities

| Function | Result and limits |
| --- | --- |
| CPU | Four Cortex-A53 cores attach and boot NetBSD 11 userland |
| Boot and root storage | Physical eMMC boot; FFSv2 root within the existing UDISK GPT partition |
| Serial console | UART on J1, 115200 baud for interactive boot interception; USB-only signed recovery and installation tested on one unopened factory sample |
| Ethernet | IP101 PHY, 100 Mbps full duplex; native SSH and image transfers tested |
| Framebuffer | Vendor display handoff, genfb and software wsfb; upright 1280x800 awesomeWM with real terminal/clock windows |
| Touch | GT9271 firmware 1020, TWI3 address 0x5d; physical press, drag, release and corrected landscape directions tested |
| I2C | S_TWI0 for MCU/PMIC/RTC and TWI3 for touch tested; other buses not validated |
| External watchdog | MCU7502 firmware 17.03.07 keepalive tested; stopping it can power-cycle the tablet |
| RTC | PCF8563 read and time across reboot tested |
| Audio | Audible audio(4) playback; a captured phrase was intelligible after application gain compensation; bounded simultaneous streams tested; clean startup/sustained use unverified; routes default to disabled |
| USB-A host | EHCI/OHCI, powered four-port hub and Pixhawk6X CDC serial tested through an ordinary eMMC reboot; other peripherals/sustained transfers unverified |
| Wi-Fi | Opt-in SDIO RAM diagnostic identifies 024c:d723, reads registers and verifies function enable/ready/restore; radio initialization and association remain unimplemented |
| GPU, Bluetooth, USB-C peripherals | Not validated |

Touch is one wscons pointer, polled every 20 ms. There is no multitouch
gesture API, interrupt-driven input or suspend/resume validation. Longer
uptime with MCU keepalive does not establish sustained system stability.

## Experimental audio driver

The [A133 audio(4) adapter](../../sys/arch/arm/sunxi/sun50i_a133_codec.c)
is selected by `EMBER64_A133_AUDIO`, which includes the eMMC configuration.
It builds natively with NetBSD 11/aarch64 GCC 12.5. On the physical sample,
the reviewed kernel boots from eMMC and enumerates `a133codec0` and `audio0`.
Both mixer routes remain disabled after reboot. See the
[driver validation receipt](validation/2026-10-08-a133-audio-driver.md).
Two subsequent audio(4) speaker tests were heard by the operator. A bounded
MIC1 recording completed through the same driver without registered FIFO
errors. A subsequent short simultaneous playback/capture test completed and
recorded the playback tone at the mic input. A subsequent captured phrase was
heard intelligibly after application gain compensation; general speech quality,
acoustic level and sustained streaming remain unverified. See the
[physical stream receipt](validation/2026-10-08-a133-audio-streams.md).

Attachment maps resources and enumerates audio without preparing clocks,
enabling interrupts or starting streams. Both mixer controls default to
disabled: `outputs.route` accepts `speaker`, and `record.route` accepts `mic1`.
Only explicit route enable prepares hardware, in sleepable thread context;
running streams reject route changes. No playback or recording runs at boot.
The adapter checks buffer ownership, format, block size and route state before
trigger. Interrupt service transfers at most 128 samples per direction and
counts faults and underrun/overrun events. DMA and suspend/resume are not claimed.

The [register lease](../../sys/arch/arm/sunxi/sun50i_a133_codec_io.c) restores
owned codec state, clocks and the PF6 GPIO while preserving unrelated pins.
It never asserts the codec bus reset: that would erase unowned bias, DAP and
calibration state. If it releases an initially held reset, reset deliberately
stays released after final disable; the original clock gates are restored.
A PLL timeout before release retains the original reset state. This is a
documented exception to full CCU-state restoration, not a hardware validation.

The [I/O contract](../tools/a133-audio-io-test.sh) includes a reset-aware bank,
PLL timeout, calibration preservation and finite FIFO transfers. The
[adapter contract](../tools/a133-audio-interface-test.sh) executes production
format, trigger/halt, interrupt and service functions: finite blocks, wrap,
signed capture words, flush timeout, impossible counts and no callbacks after
halt. Allocation/free and mixer IRQ establishment are reviewed and compiled;
their complete lifecycle is not executed by that portable fixture.

The [A133 PCM core](../../sys/arch/arm/sunxi/sun50i_a133_pcm.c) validates mono
16-bit playback/capture and stereo playback at 16 or 48 kHz. It constructs
FIFO format words with stream, IRQ and DMA enables cleared. A caller must
validate signed little-endian encoding/precision, then supply the resulting
frame size when initializing a ring with at least two equal aligned blocks.
Copy each `a133_pcm_ring_chunk()` span before `a133_pcm_ring_advance()`;
serialize access under the driver's interrupt lock. Block completion
means the memory span has been transferred, not that the hardware has played it.

The [format/ring contract](../tools/a133-pcm-test.sh) runs the production source
without hardware access. On native NetBSD, the
[kernel-context check](../tools/a133-pcm-kernel-check.sh) accepts a source root
and a configured kernel compile directory, and compiles with its real flags.
These checks do not exercise the physical codec. The experimental configuration
selects the core and adapter; keep physical acceptance separate from software
contracts and the native kernel-context compilation check.

On the physical sample a two-second, 16 kHz mono direct-register HPOUT probe
was audible with PF6 low. The PF6-high comparison has no confirmed acoustic
result, so amplifier polarity is not isolated and verified. Microphone FIFO
capture is bounded diagnostic evidence; sustained duplex and general speech
quality remain unverified. AVCC and CPVIN are 1.8 V;
do not substitute 3.3 V supplies. No audio test runs automatically at boot.

Daytime acceptance used `audioplay` with a synthetic two-second 16 kHz mono
WAV and `audiorecord` with 16 kHz mono output. The native hardware formats
remained 48 kHz stereo playback and 48 kHz mono capture: the MI audio layer
converted the requested file formats. Both audible tests exited successfully;
the 4.096-second capture had a low signal and five clipped startup
samples. A subsequent 8.192-second phrase recording was intelligible after
100 ms startup trimming, DC removal and 5.4x application gain. One controlled
phrase and an operator-confirmed voice application reply do not establish
general recognition quality or clean stream startup.
The subsequent simultaneous-stream recording contained the playback tone
without clipped samples; acoustic pickup versus electrical crosstalk remains
unisolated. Control-device sample/open fields refer to its own file descriptor;
use driver event counters and the recorded data for transfer evidence.

## Resource adaptation

The USB-A path translates only the verified USB1 controller resources and
board power GPIOs. It retains USB0/USB-C ownership and the other GPIO banks.
The PHY enables the internal hub and four downstream power gates, then the
generic EHCI/OHCI drivers enumerate the hub and CDC serial device. Legacy
seven-cell GPIO bindings are decoded without treating output mux selection
as an active-low flag. See the
[USB host receipt](validation/2026-10-08-a133-usb-host.md).

The vendor tree uses legacy device names and resource cells. The A133-only
[FDT adapter](../../sys/arch/arm/sunxi/sun50i_a133_fdt.c) translates resources
needed for MMC, the active I2C controllers and the existing scanout reservation.
It also marks audio only after checking the inspected codec/machine phandle,
address/size, six-cell PF6 GPIO, PA polarity/delay and SPI25 interrupt. The
[audio FDT contract](../tools/a133-audio-fdt-test.sh) checks these guards,
disabled/mismatched nodes and removal of a stale marker.
It retains unrelated consumers and leaves other board families unchanged.

TWI3 uses PH12/PH13 in function i2c3, the A100 CCU bus-i2c3 clock and reset.
PH13 must remain touch SDA: an earlier Ethernet workaround claimed it as
a guessed 25 MHz clock and prevented touch communication. The verified
Ethernet route needs PH9/PH10 and the PH11 PHY reset, and preserves PH12/PH13.

The reset helper is deliberately limited to the inspected YS-M33 vendor
resources: PH14 reset and PL10 INT/address selection. The adapter checks the
GPIO provider handles, ports and pins before marking that child. The driver
also requires the A133 root, address 0x5d and the physical GT9271 product ID.
Its 20/6/50/10 ms reset sequence preserves PL0/PL1 for the MCU I2C bus.
Legacy six-cell GPIO providers remain intact; canonical GPIO conversion is
follow-up work. Do not apply this helper to an unverified panel or board.

The matching A133 wsfb/ws input patches and Xorg session configuration
remain in the local sample deployment; a published A133 graphics recipe
is not yet available in Ports.
The framebuffer needs clockwise rotation. This sample's touch coordinates
already increase right/down in its landscape mount and need no input rotation.

## Opt-in SDIO discovery

The early FDT adapter can translate the inspected MMC1 resources only when
vendor U-Boot's root tree has the zero-length `ember,ys-m33-sdio-probe`
property. It validates the PG0..PG5 group, WLAN PL5/PL6 references, address
mapping and interrupt/GPIO providers. It rejects alternate IRQ/GPIO paths
and PIO `vcc-pg-supply`, and removes MMC voltage/UHS references. It introduces
no radio power sequence or PMIC writes. Removing opt-in disables a host
previously marked by this adapter; default boot does not opt in.

On this sample a native RAM-only kernel identified SDIO function 1 as
manufacturer `0x024c`, product `0xd723`, interface code `0x07`, at four-bit
width and 25 MHz. A network driver, firmware loading, WPA association and
reconnect are still required. No Wi-Fi
profile or credentials were tested. This warm-boot result does not establish
cold radio power sequencing. See the
[SDIO validation receipt](validation/2026-10-08-a133-sdio-probe.md) and
[production-source contract](../tools/a133-sdio-fdt-test.sh).

The separate `EMBER64_A133_SDIO` configuration adds a one-shot read-only
`rtl8723dsprobe` attachment, requiring an additional zero-length root
`ember,ys-m33-rtl8723ds-read-probe` property. It checks the actual MMC1 parent
and common function-0 CIS before issuing CMD52 reads. Per-function MANFID
is absent on this sample. The physical RAM diagnostic read SYS_CFG1
`00413131`, SYS_CFG2 `0000000f` and HCI suspend control `03`; a second SYS_CFG1
read agreed. CCCR enable/ready stayed `00/00`. Without the function opt-in it adds no function
enable, register writes, CMD53, firmware, IRQ handler or network interface.
The installed eMMC kernel retains the working audio/USB build. See the
[register-read receipt](validation/2026-10-08-a133-rtl8723ds-read.md) and
[read transport contract](../tools/rtl8723ds-read-test.sh).

The additional zero-length `ember,ys-m33-rtl8723ds-function-probe` root property
permits only checked function-zero IOEx writes. A RAM kernel observed
function 1 ready (`02`), repeated SYS_CFG1 and restored original IOEx (`00`).
Polling is bounded; host/card errors and ambiguous-write restoration are
covered by the [lifecycle contract](../tools/rtl8723ds-function-test.sh).
This does not power the radio or create a WLAN interface. See the
[physical function receipt](validation/2026-10-08-a133-rtl8723ds-function.md).

Cable-only installation on a closed factory tablet and an own second-stage
loader are separate, unvalidated workflows. See the
[installation boundaries and read-only preflight](ys-m33-a133-cable-install.md).

## Build and deployment boundaries

An unopened second sample completed cable-only installation, Ethernet SSH,
awesomeWM startup and a normal eMMC restart without UART. A timed first-boot
reboot returned to signed USB recovery before acceptance. See the
[installation receipt](validation/2026-10-08-a133-cable-install.md).
Cold power-cycle acceptance and full factory restoration remain untested;
the first sample's physical audio and touch checks do not establish them on
the second tablet.

Export a clean pinned commit and build `EMBER64_A133_EMMC` or the guarded
`EMBER64_A133_AUDIO` configuration natively using
the matching NetBSD 11 kernel tools. It selects `wedge:UDISK` as FFS root.
For the vendor boot partition, [a133-boot-image.rb](../tools/a133-boot-image.rb)
packs the resulting ARM64 `netbsd.img` into an Android v2 container. Use an
empty ramdisk for the eMMC-root configuration. The tested audio container
retains the DTB payload from its preceding working container; its original
provenance is not established. At boot, vendor U-Boot supplies the inspected
full board tree used by the audio resource guard. Neither firmware nor a
personalized filesystem belongs in this repository.

Deployment requires a backup, inspected GPT partition bounds, the original
recovery path and complete write/readback hash checks. The tested root occupies
only the initial 4 GiB of UDISK; the GPT and other Android/recovery partitions
are preserved. A generic whole-device image must not be substituted for that
scoped installation. Current storage setup is a manual sample adaptation.

Build [mcu7502-keepalive.c](../tools/mcu7502-keepalive.c) with `-lutil` and install
its [rc service](../tools/mcu7502-keepalive.rc) before unattended boot. It verifies
firmware 17.03.07 and services the MCU at address 0x16 every 20 seconds.
The recovery OS needs its own compatible keepalive before lengthy operations.
A command acknowledgement for watchdog disable did not prevent actual resets;
the successful keepalive path is the supported one for this sample.

## Evidence, 2026-10-07

Physical kernel `EMBER64_A133_EMMC #7` was built from the clean source snapshot
`e3a29bd310539c0f9123ac72069fdbe827a5fdf9`. The Android boot container was
17,000,448 bytes; its write/readback MD5 was
`c12f6372bcd6c696674bdef335acba05`. Native kernel and module builds passed.
Four production-source contracts passed on host and native AArch64:
FDT adaptation/isolation/idempotence, Ethernet pin ownership, Goodix frames
and the board reset timing/ownership sequence.

The physical boot log identified GT9271 firmware 1020 and wsmouse0; Xorg
attached that real wscons pointer. Sensor and X input logs recorded press,
movement and release. Ordered physical corner taps established the coordinate
orientation, and the operator confirmed correct cursor directions and menu
interaction. The saved configuration reloaded after an Xorg restart and an
OS reboot, without a temporary coordinate matrix. The exact-zero X input
regression also passed using the real upstream wsReadInput routine.

This receipt establishes a short, single-sample boot and GUI/input workflow.
Audio speech and sustained duplex, Wi-Fi association, the final application,
uninterrupted long runs,
module removal while in use, cold power loss and new boot firmware remain
separate acceptance work. Cosmetic boot artwork does not change AVB state.
