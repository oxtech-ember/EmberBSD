# A733 DE3.52 native DMA preparation

`sun60i_a733_de352_dma.c` allocates one CPU color-bar plane and one RCQ
list through native `bus_dma`. It performs no MMIO. This component does not
establish IOMMU bypass, clock ownership, RCQ completion or scanout.

## Caller contract

The caller must establish that the DE0 master uses the supplied DMA tag.
A missing IOMMU provider and a fallback tag do not prove identity mapping.
The caller must serialize every operation on the returned object.

`sun60i_a733_de352_dma_prepare` accepts a width from 1 through 1920 and a
height from 1 through 1080. These limits bound allocation; they do not select
an HDMI mode. The output provider must validate the actual mode.

The allocator creates a child DMA tag below 4 GiB. Each buffer has one
contiguous device-visible segment. The address is page aligned. The entire
mapped span must fit below 4 GiB. The buffers must not overlap. Allocation
failures unwind in reverse order and leave the caller's output unchanged.

The XRGB8888 plane has a 64-byte-aligned pitch. Every allocated byte is
initialized. The visible rows contain eight color bars. Row and page padding
remain zero. Pixel bytes are explicitly little-endian B, G, R, X.

The 4096-byte queue contains two 16-byte RCQ descriptors. The first describes
seven layer words at `DE+0x1c1000`. The second describes the one pipe-control
word at `DE+0x281000`. Their source offsets are 32 and 64. All unused bytes
remain zero. See the [format contract](a733-de352-format.md).

The native submitter must own both destination blocks. It must validate
reserved fields and inactive processing blocks before it writes addresses.
The fixed list is 32 bytes; this component does not assert the full writable
width of the hardware list-length register.

`sun60i_a733_de352_dma_publish` performs `BUS_DMASYNC_PREWRITE` on both full
maps. It then marks the object as published. Call it before the first
attempt to write an address register. After publication, destruction returns
`EBUSY`, including after a failed write or timeout. There is no unpublish API.
A future stop path needs separate proof of engine stop or isolation.

## Validation and limits

Origin: EmberBSD, AI-assisted, original BSD-2-Clause implementation. The
allocator uses the native EmberBSD `bus_dma` contract. Register data use the
pinned facts and license boundary in the linked format contract.

```sh
python3 ember/tools/a733-de352-dma-contract.py
DE352_CFLAGS='-fsanitize=address,undefined -fno-omit-frame-pointer' \
    python3 ember/tools/a733-de352-dma-contract.py
```

The fixture compiles the actual allocator and formatter bodies. Native DMA
calls are controlled doubles. It checks each allocation failure, exact
cleanup, range and segment rejection, descriptor bytes, initialized padding,
synchronization and retention. `CC`, `DE352_SOURCE_ROOT`, `DE352_CFLAGS` and
`TEST_RUNNER` select the host compiler, source, flags and execution wrapper.
These checks do not accept physical DMA or a visible frame. Clock, memory
path, native DE submission, HDMI output and KMS remain separate acceptance
steps.
